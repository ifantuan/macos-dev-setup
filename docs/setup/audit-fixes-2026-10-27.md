## 有意调整的行为

- `make full` 仍只安装软件与配置；完整恢复链使用 `./scripts/quickstart.sh --profile full`。
- 默认 core/full 不再声明第三方 tap。Bun、OpenCode 使用官方 core。ZedG、Rebased 的上游定义都包含移除 macOS 隔离属性的操作，改为个人示例中的注释项，不自动安装或授权。出处见 [ZedG 定义](https://github.com/x6nux/homebrew-zedg/blob/main/Casks/zedg.rb)和 [Rebased 定义](https://github.com/DetachHead/homebrew-tap/blob/main/Casks/rebased.rb)。这是来源及安装步骤核验，不代表对这些软件完成全面安全审计。
- `--cleanup-preview` 返回 1 时，可能是有待清理项，也可能是真实错误；不再猜测为成功。所有输出保留，调用方应先检查诊断。
- `--cleanup-force` 需要额外的 `--acknowledge-trust-reset`；即便传了 `--yes` 也不例外。Homebrew 会用选中清单替换全局显式信任，默认官方源清单会移除全部显式第三方授权。只有接受该影响时才执行；多份私有清单不能被一个不完整公共清单代表。
- Java 安装不再永久修改用户的 SDKMAN 配置。`sdk` 每次调用都会重读 `~/.sdkman/etc/config`，环境变量无法关闭“是否设为默认”询问，因此安装命令断开标准输入，按 SDKMAN 默认答案执行。下载器与日志 FIFO 使用私有临时目录。
- 清单按短名称声明 `bun`、`opencode`、`cc-switch` 等，已从第三方 tap 安装的机器仍会通过 `brew bundle check`，但强制清理可能移除对应信任和 tap。`--cleanup-force` 通过 `brew ruby scripts/lib/find-shadowed-packages.rb` 由 Bundle 解析清单、读取已安装 formula 和 cask 的实际来源，并使用 `Bundle::Trust.entries` 与 `Homebrew::Trust.target` 核对清理后的授权。没有相应授权时拒绝清理；完整名称本身不是信任声明，正确的按包、按 tap 授权则允许继续。来源或清单解析失败时同样取消清理。
- 迁移命令按 formula、cask 分别输出，参数进行 Shell 转义；审查并确认清单指向目标来源后再执行。cask 命令不加 `--zap`，但不承诺所有应用卸载脚本都保留数据。含中文、空格、单双引号、美元符号及反引号的路径已通过 Bash 和 zsh 命令桩验证。
- bootstrap 遇到父目录为链接的配置（例如 dotfiles 工具把 `~/.config` 链接到其他目录）时，只跳过受影响的配置并在结尾汇总，不写穿链接，也不阻断软件安装和其他配置。父路径为悬空链接或普通文件时仍在写入前拒绝执行。
- 替换已有普通文件时沿用其原权限，例如用户设为 600 的 `~/.zshrc` 替换后仍为 600；同样适用于备份和反向同步写回仓库的文件。
- `doctor`、环境审计和维护检查使用 `--no-upgrade` 验收已安装状态，与默认安装策略一致；查看过期版本另用 `brew outdated`。

## 备份与恢复

bootstrap 的批次目录为 `~/.macos-dev-setup-backup/<时间戳>.<随机后缀>/`；`BACKUP_DIR` 可替换其父目录。原配置按家目录中的相对路径存放。链接本身保留在原相对位置，可读取的原目标内容放在批次的 `link-targets/` 下。

恢复前先保存当前配置，再选择正确批次：普通文件恢复其内容；符号链接应恢复保存的链接文本，而不是解引用后复制。相对链接在备份目录中可能暂时悬空，恢复到原位置后才按原基准解析。安装不会改写链接指向的原文件；如果那个文件后来也被修改，可以从 `link-targets/` 取回内容。当前仍采用人工恢复，没有新增一键恢复脚本。

强制清理前的信任快照位于独立 `trust-<时间戳>.<随机后缀>/trust.json`，目录权限 700、文件权限 600。按条目复核后，可用 Homebrew 的 `brew trust --tap`、`--formula`、`--cask`、`--command` 重新授权需要的条目。不要直接覆盖 Homebrew 内部信任文件；快照不是软件或应用数据备份。

## 测试与验证

新增 [隔离回归测试](../../tests/README.md)，入口为 `make test`。首批记录为 19 项修复前失败、修复后通过，随后扩展至 27、31、33 项；这些历史阶段不代表本轮重新执行了全部历史回退。按 [追加复核报告](audit-2026-10-27-claude-followup-review.md)补齐检测与信任边界后为 39 项；随后补充真实 Homebrew 接口冒烟测试，当前共 40 项。

本轮将原先读取真实本机安装状态、仅测试未安装名称的用例替换为隔离验证：由 brew 桩运行真实仓库检测脚本，Ruby 求值清单样例，Homebrew 接口由 fixture 提供安装状态和信任数据。增加了特殊名称、语法、误匹配、cask、完整来源、显式信任、解析失败及特殊路径命令测试。这些用例使用临时 HOME；解释器优先取 Homebrew 自带的 portable Ruby，与 `brew ruby` 实际运行版本一致，没有 Homebrew 时退回系统 Ruby。接口桩发现不了 Homebrew 内部接口变化，因此另设只读的真实接口冒烟测试：有 Homebrew 时运行，验证合法写法不误报；本机装有第三方包时再验证真实信任规则的命中与放行，未安装 Homebrew 时跳过。

在临时仓库副本中恢复旧正则、移除 cask 枚举、删除路径转义，对应测试均失败；恢复后通过。另用本机真实 Bundle 解析器与信任规范化接口验证 5 个场景，HOME 与安装状态接口隔离，不执行安装、卸载、清理或信任变更。

CI 已增加系统 Bash 与 Homebrew Bash 两套运行，保留严格 ShellCheck、Gitleaks、Ghostty 校验和恢复演练。新增版本基线与共享文件库纳入 Shell 语法和 ShellCheck 检查；来源检测 Ruby 脚本的语法检查也已加入 CI 和 doctor，使用 `brew ruby -- -c`，与实际运行的解释器一致；doctor 在没有 brew 时退回系统 `ruby`，两者都没有则跳过。
